# xQuakShell frontend

The Svelte 5 + TypeScript renderer, built by Vite and embedded into the Go binary at build time —
`main.go` serves `frontend/dist` through `go:embed`, so a stale `dist` is a stale application.

Nothing here is a standalone web app: every call to the backend goes through the Wails bridge, which
only exists inside the desktop window. `npm run dev` alone gets you a page that cannot reach Go; use
`make dev` from the repository root to run the real thing with hot reload.

## Commands

| Command | What it does |
|---------|--------------|
| `npm install` | Dependencies. `make install` from the root runs this. |
| `npm run build` | Production build into `dist/`. Required before any Go build or `make lint`/`make gosec`, which type-check the module and need the embedded directory to exist. |
| `npm run check` | svelte-check. **Zero errors** is a merge gate. |
| `npm test` | The unit suites, run as plain `tsx` scripts — no test runner, no globals. |
| `npm run budgets:update` | Re-records the `.ts` / `.svelte` half of the size baseline. Prefer `make budgets-update` from the root, which does both halves. |

Node 20.19+ or 22.12+ — Vite 8 refuses to start on anything older.

## Layout

Dependencies point one way: a component never reaches past `actions/` to the bridge.

| Directory | Responsibility |
|-----------|----------------|
| `src/backend/` | `liveGateway.ts` is the **only** place that touches `window.go` / `window.runtime` |
| `src/api/` | One thin wrapper per backend RPC, routed through `callBackend`. No store access |
| `src/actions/` | Orchestration: combines `api/*` calls with store updates |
| `src/stores/` | Global reactive state |
| `src/lib/` | Components — local state and rendering |
| `src/hotkeys/`, `src/events/`, `src/logSurface/`, `src/terminal/` | Focused subsystems used by the above |
| `src/logviewer/` | The separate debug log-viewer window |
| `App.svelte` | Layout composition, no domain logic |

`src/architecture.test.ts` enforces this: reaching `window.go` outside the gateway allowlist fails
the build, as does an `api/*` module importing a value binding from `stores/appState`. Both
allowlists are closed — extending one needs the same scrutiny as the original finding.

`wailsjs/` is generated by Wails. Do not edit it, and do not hold it to the rules above.

## Size budgets

350 code lines per `.ts` file; 200 in a `.svelte` script block and 400 in the file overall. Comments
are free, so explaining a thing never costs you budget. Limits, exemptions and the frozen baseline
live in `code-budgets.json` at the repository root; `src/architecture/measure.test.ts` and
`funcShapes.test.ts` enforce them, and the baseline is a ratchet in both directions — a file that
shrinks without being re-recorded fails just as one that grows does.

## Tests

Tests are `.test.ts` files next to what they cover, executed directly by `tsx` and registered one by
one in `package.json`. A new test file is not picked up until it is added there.

They assert behaviour at its boundaries rather than reaching for a mock: `src/lib/tiles/geometry.test.ts`
is the model to copy. Before claiming a test covers something, break the line it covers and confirm
it goes red.
